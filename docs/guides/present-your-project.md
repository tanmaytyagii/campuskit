# Present your project

CampusKit has three tools for the last stretch before a submission or a viva: the interactive demo, presentation mode and the readiness check. They all work in your browser and save nothing outside it.

## 1. Practise with the interactive demo

Open a project and choose **Try the interactive demo**, or choose **Demos** in the site's menu. The demo is a demonstration with fictional sample data, not a live system:

- **Attendance and expense demos:** they use the template's own code for calculations, validation and saving changes, so the numbers and messages match the project you download.
- **Result analyzer demo:** the real project is a Python app. The demo is a browser version written in TypeScript, checked against the Python code's results. Your browser doesn't run Python.
- **Your changes:** they stay in the browser tab until you close it. **Reset to the example** brings the sample data back.

Two helpers are on the demo page:

- **Take the tour** walks through the screens and how they map to the project's code.
- **Practise the demo** gives you each step of a demonstration: what to say, what to do and what should happen. When a step changes the data, the demo checks that you really did it. If you finish with every checked action done, the date is saved in your browser for the readiness check.

## 2. Present with slides

**Present the project** opens presentation mode: full-screen slides in the order examiners expect.

1. Introduction
2. Problem
3. Learning objectives
4. Features
5. Architecture
6. How it works
7. Technology
8. Demo
9. Limitations
10. Conclusion

- **Where the content comes from:** everything on a slide comes from the project's own description, learning guide or demo. A label at the bottom says which.
- **Speaking notes:** CampusKit's suggestions for what to say. Press **N** to hide them when the screen is shown to an audience.
- **Moving around:** use **←** and **→** (or Page Up and Page Down) between slides, **Home** and **End** for the first and last, and **Esc** to leave. Keys you type inside the demo don't move the slides.
- **Demo slides:** they contain the live demo, with the same data as the demo page.

Presentation mode doesn't create PowerPoint or PDF files. If you need slides for your institution, use these as a plan and make your own.

## 3. Check your readiness

**Check your readiness** lists eleven things to have done before you submit and present, in three groups: get it running, understand it, and present and submit it.

### Where each status comes from

| Label                | What it means                                                                                                                                                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Checked by CampusKit | CampusKit checked it itself: the template's verification records, the setup steps it publishes, the demo's own checks or the prompts left in your saved report draft. |
| From your progress   | Worked out from your own ticks in the learning checklist and your own viva ratings.                                                                                   |
| You confirm          | Installing the prerequisites, running the project and running its tests happen on your computer, which CampusKit can't see. Tick them yourself when they are done.    |

Opening a page never counts as doing something. The template's verification is about the files CampusKit publishes. It says nothing about the copy on your computer.

### How the score is worked out

Each item counts once: **Ready** counts 1, **In progress** counts ½ and **To do** counts 0. The percentage is the total divided by the number of items. It describes your preparation in CampusKit, not the quality of your project, and it isn't a grade.

| Item                       | Ready when                                                               |
| -------------------------- | ------------------------------------------------------------------------ |
| The template passed checks | The template's current files have a passing verification record          |
| Setup instructions         | The project publishes setup steps (always true for published templates)  |
| Prerequisites, run, tests  | You tick them                                                            |
| Architecture               | Every architecture item in the learning checklist is ticked              |
| Main features              | Every functionality, data and validation item in the checklist is ticked |
| Limitations                | Every limitation and improvement item in the checklist is ticked         |
| Viva questions             | Every question is practised and none is marked “Review again”            |
| Demonstration              | You finished the guided demo with every checked action done              |
| Report draft               | Your saved draft has every section and no [bracketed prompts] left       |

Partly done items count as In progress. **Clear my confirmations** unticks only the three items you confirmed yourself.
